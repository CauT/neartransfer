# 近传验收记录

日期：2026-10-30（Asia/Shanghai）。目标已由 Mac + Android 原生 App 改为 Mac App 自动启动 H5、局域网浏览器双向互传。

## 用户入口与预期

正常打开 `NearTransfer.app`，出现控制窗口，默认浏览器自动打开 H5。Mac 与另一设备处于同一局域网；另一设备扫描页面二维码打开浏览器。两端各发送中文文字、图片、文件，另一端可看到并查看/保存原始内容。退出应用关闭监听，重新打开保留历史、更新配对凭据。网络中断和失效配对给出可读提示，不修改代理、VPN、信任库或防火墙。

## 已执行结果

| 范围 | 结果 | 证据与限制 |
| --- | --- | --- |
| Mac 正常启动 | 通过 | 通过桌面 UI 打开构建的 App，自动打开 Chrome H5，显示在线状态、二维码和局域网地址；后续正常启动恢复已有 4 条测试内容。初始默认数据目录不存在，启动后自动创建。 |
| Mac 控制窗口 | 通过 | 窗口从“正在启动”变为“正在运行”，提供打开界面、数据目录、退出入口。 |
| 二维码内容 | 通过 | 从实际页面读取 PNG，使用 CoreImage 二维码解码器得到与页面连接链接完全一致的内容。沙箱内解码失败；在允许系统图像服务的环境重跑通过。未使用手机相机扫码。 |
| 两端连接与文字互传 | 通过（同一 Mac 两个浏览器上下文） | Chrome loopback 页面与局域网 IPv4 页面互发中文和含查询参数的 URL，实际打开文字弹窗核对。不能替代跨物理设备/路由器验收。 |

| 原始字节保存 | 通过 | 接收的 PNG SHA-256：`0673abdf4c4585f21c4939bc868ee95b7dc7f564b8a4047f91e1cdd0c7025442`；1 MiB 二进制：`fbbab289f7f94b25736c58be46a994c441fd02552cc6022352e3d86d2fab7c83`，均与原件一致。 |
| HTTP 下载协议 | 通过 | `scripts/check-lifecycle.py` 运行打包引擎，以 mac/browser 两种来源各上传约 2 MiB 二进制，然后使用原生表单等价 HTTP POST 下载，SHA-256 一致。服务器和真实 HTTP 客户端测试包含下载鉴权。 |

| 窄屏布局 | 已检查并修正 | 390×844 预览发现长文件名挤压操作按钮，修正为两列网格和独立按钮行。最终复查与截图见本地 build/acceptance。不等同于 Android/iOS 真机。 |

## 交付边界

- 这是本机 arm64、macOS 13+ 开发版本。App 内嵌 Go 引擎和 H5，无运行时外部依赖。
- HTTP 明文，仅可信局域网；二维码/链接可访问当前收件箱全部内容。页面明确告知，不宣称加密传输。
- 没有真实手机、第二台物理设备、1 GiB 极限文件、后台持续上传、IPv6、企业 Wi-Fi 隔离、防火墙拒绝路径的验收。
- 没有 Developer ID、公证、Gatekeeper 下载后安装验收。
- **完整交付验收尚未完成**：需要在允许正常下载的浏览器和实际第二台设备验证扫码、双向图片/文件保存。不以单元测试、二维码可见或列表有内容代替这些结果。
- 截图及测试原件位于忽略的 `build/acceptance/`。二维码截图属于会话凭据，勿公开有效会话的截图。测试收件箱保留，不自动删除。
